# Test and release-quality strategy

## Test layers

### Go unit tests

- Auth hash/session/CSRF/lockout, expiration and token-at-rest behavior.
- Configuration precedence and production fail-closed validation.
- Identifier/prefix/username validation.
- URL encoding and TLS parameters.
- Protected resource policy.
- Redis preset/allow-list expansion and unknown-command rejection.
- Fernet known-answer vectors and wrong-key/tamper behavior.
- Secret redaction in errors/logs/audit.
- State-machine compensation for create/rotate/duplicate.

### HTTP tests

- Every route auth requirement, method, content type, body limit, unknown fields.
- Origin/Referer and CSRF matrix.
- Cookie attributes and session rotation/expiry.
- Stable error codes and request IDs.
- `Cache-Control: no-store` on every credential-bearing response and error path.
- Protected/destructive confirmations and reauthentication.
- No credential in GET responses or audit metadata.

### Frontend tests

- Login/bootstrap/session expiration.
- Credential ticket copy/dismiss/clear behavior; no storage calls.
- PostgreSQL/Redis create, rotate, delete confirmations and errors.
- Selection changes clear previous secret/details.
- Loading, degraded, stale, and partial-failure states.
- Keyboard/focus/dialog behavior and accessible names.

### Integration tests

Run ephemeral PostgreSQL 17 and Redis 8 services in CI:

- PostgreSQL restricted role/database ACLs, direct URL, catalog inspection, rotate, duplicate ownership isolation, protected-drop rejection, terminate-self exclusion, cleanup behavior.
- PgBouncer direct-vs-pooled compatibility and authentication.
- Redis TLS/plaintext rejection policy, ACL create/update/enable/disable/rotate/delete, old-password rejection, cross-prefix denial, dangerous command denial.
- Representative frameworks/workloads for every Redis preset, including Lists, Streams consumer groups, and Sorted Sets.
- Legacy Fernet records generated by Python and copied-record dry-run fixtures.
- SQLite backup/restore/integrity under WAL activity.

### Deployment tests

- Fresh Ubuntu VM install, second-run idempotency, update, rollback.
- Existing-PostgreSQL clone install with invariant checks.
- Firewall/listener checks from local and external probes.
- Cloudflare route configuration tested in a non-production zone/profile where automation is allowed.
- Cert renewal hook rehearsal with staging ACME where possible.
- Full backup and isolated restore.

## Required commands (target)

```bash
go test ./...
go test -race ./...
go vet ./...
go build ./cmd/redgres
cd web && npm ci && npm test -- --run && npm run build
```

Add formatter/linter, vulnerability, secret, SBOM, and shell checks in CI:

- `gofmt`/`go vet` plus selected pinned linter.
- `govulncheck`.
- npm audit policy with reviewed exceptions.
- Gitleaks or equivalent.
- ShellCheck and Bats/VM tests for deployment scripts.
- dependency/license/SBOM generation.

## Test data safety

- Integration tests default to ephemeral local containers and refuse hostnames outside an explicit allow-list.
- Destructive tests use random test prefixes/databases and verify target identity.
- Never load production secrets into ordinary CI.
- Copied vault ciphertext tests run in an isolated protected environment; fixture outputs contain no plaintext production password.

## Release gate matrix

| Gate | Required evidence |
|---|---|
| Pull request | Unit + HTTP + frontend, static checks, docs/traceability |
| Merge to main | Integration PostgreSQL 17/Redis 8, build, secret scan |
| Release candidate | Fresh/existing install rehearsal, upgrade/rollback, backup/restore |
| Production cutover | Live preflight, current backup, external TLS/Access tests, operator approval |
| Legacy retirement | Observation window, parity signoff, restore test, rollback rehearsal |

Flaky tests are failures to investigate, not rerun-until-green evidence.
