# Test and release-quality strategy

## Test layers

### Go unit tests

- Auth hash/session/CSRF/lockout, expiration and token-at-rest behavior.
- Configuration precedence and production fail-closed validation.
- Identifier/prefix/username validation.
- URL encoding and TLS parameters.
- Protected resource policy.
- Redis preset/allow-list expansion and unknown-command rejection.
- Fernet known-answer vectors and wrong-key/tamper behavior.
- Secret redaction in errors/logs/audit.
- State-machine compensation for create/rotate/duplicate.

### HTTP tests

- Every route auth requirement, method, content type, body limit, unknown fields.
- Origin/Referer and CSRF matrix.
- Cookie attributes and session rotation/expiry.
- Stable error codes and request IDs.
- `Cache-Control: no-store` on every credential-bearing response and error path.
- Protected/destructive confirmations and reauthentication.
- No credential in GET responses or audit metadata.

### Frontend tests

- Login/bootstrap/session expiration.
- Login composition without authenticated-shell/dependency leakage across mobile and desktop.
- Sidebar, tablet icon rail, mobile navigation drawer, topbar owner menu, and route/focus restoration.
- Global search keyboard/pointer/touch behavior, service grouping, bounded/degraded states, secret exclusion, and destructive-action rejection.
- Credential ticket copy/dismiss/clear behavior; no storage calls.
- PostgreSQL/Redis create, rotate, delete confirmations and errors.
- Selection changes clear previous secret/details.
- Loading, degraded, stale, and partial-failure states.
- Keyboard/focus/dialog behavior and accessible names.
- Responsive behavior at 360×800, 768×1024, 1280×800, and 1600×1000 plus 200% zoom, long identifiers, dense grids, safe areas, and no viewport overflow.

### Integration tests

Run the complete ephemeral service matrix from [COMPATIBILITY.md](COMPATIBILITY.md) in CI: PostgreSQL 17 and 18 crossed with Redis 8.2 and 8.8. PgBouncer behavior is exercised against each supported PostgreSQL major.

- PostgreSQL restricted role/database ACLs, direct URL, catalog inspection, rotate, duplicate ownership isolation, protected-drop rejection, terminate-self exclusion, cleanup behavior.
- PgBouncer direct-vs-pooled compatibility and authentication.
- Redis TLS/plaintext rejection policy, ACL create/update/enable/disable/rotate/delete, old-password rejection, cross-prefix denial, dangerous command denial.
- Representative frameworks/workloads for every Redis preset, including Lists, Streams consumer groups, and Sorted Sets.
- Legacy Fernet records generated by Python and copied-record dry-run fixtures.
- SQLite backup/restore/integrity under WAL activity.

### PostgreSQL provisioning and extension tests

For every capability/major combination claimed by a release under [POSTGRESQL_PROVISIONING.md](POSTGRESQL_PROVISIONING.md):

- fresh install resolves exact signed packages and enables only the named databases;
- existing `preserve` mode inventories but changes no packages, configs, preloads, service state, database schemas or `template1`;
- an apply plan rejects unknown capabilities, unavailable/wrong-major packages, package-source drift, changed plan digest, protected/unknown databases and insufficient backup/capacity;
- preload lists merge without dropping existing entries; reload/restart classification is correct; restart refuses without explicit approval;
- approved restart drains/pauses PgBouncer, restarts PostgreSQL once, verifies direct health, resumes PgBouncer and verifies pooled clients;
- extension version/schema/owner and capability smoke queries are checked per named database; a second plan is no-op;
- restore installs exact required extension files before loading the dump and verifies extension-owned metadata/data;
- pg_repack client/server mismatch and disk shortage fail before maintenance; TimescaleDB tuning is never auto-applied; pg_partman has one scheduler; pg_cron uses one control database; pgAudit policy/log-volume checks are explicit.

Matrix jobs must report detected full versions and immutable container digests. A green job using an unreported/floating `latest` image is not compatibility evidence. Version/capability preflight tests also cover unsupported versions, unparseable versions, expected-version mismatches, and prerelease rejection without mutation.

### Deployment tests

- Fresh Ubuntu VM install, second-run idempotency, update, rollback.
- Existing-PostgreSQL clone install with invariant checks.
- Existing/fresh PgBouncer modes and PostgreSQL extension preserve/apply plans on disposable hosts.
- Firewall/listener checks from local and external probes.
- Cloudflare route configuration tested in a non-production zone/profile where automation is allowed.
- Cert renewal hook rehearsal with staging ACME where possible.
- Full backup and isolated restore.

## Required commands (target)

```bash
go test ./...
go test -race ./...
go vet ./...
go build ./cmd/redgres
cd web && npm ci && npm test -- --run && npm run build
```

Add formatter/linter, vulnerability, secret, SBOM, and shell checks in CI:

- `gofmt`/`go vet` plus selected pinned linter.
- `govulncheck`.
- npm audit policy with reviewed exceptions.
- Gitleaks or equivalent.
- ShellCheck and Bats/VM tests for deployment scripts.
- dependency/license/SBOM generation.

Dependency/toolchain update changes additionally record old/new exact versions, official release/security notes, compatibility or migration impact, lockfile/checksum diff, vulnerability/license result, and full affected test/build evidence. Automated update pull requests never merge solely because dependency resolution succeeds.

Use browser-level automation for the responsive shell, search palette, login/session transitions, keyboard focus, and critical credential/destructive workflows. Component tests alone are insufficient for viewport overflow, drawer focus, sticky shell behavior, or zoom. Visual snapshots may detect drift but never replace semantic and interaction assertions.

## Test data safety

- Integration tests default to ephemeral local containers and refuse hostnames outside an explicit allow-list.
- Destructive tests use random test prefixes/databases and verify target identity.
- Never load production secrets into ordinary CI.
- Copied vault ciphertext tests run in an isolated protected environment; fixture outputs contain no plaintext production password.

## Release gate matrix

| Gate | Required evidence |
|---|---|
| Pull request | Unit + HTTP + frontend, static checks, docs/traceability |
| Merge to main | Required PostgreSQL 17/18 × Redis 8.2/8.8 matrix jobs, focused claimed-extension jobs, build, secret scan |
| Release candidate | Fresh/existing install rehearsal, selected/default version checks, upgrade/rollback, backup/restore |
| Production cutover | Live preflight, current backup, external TLS/Access tests, operator approval |
| Legacy retirement | Observation window, parity signoff, restore test, rollback rehearsal |

Flaky tests are failures to investigate, not rerun-until-green evidence.
