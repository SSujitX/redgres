## Current slice

### OPS-004 / NFR-010 isolated SQLite restore verification (2026-08-27)

Partial, not restore or production acceptance. `database.VerifySQLiteSnapshotRestore` accepts only metadata shaped like a retained `CaptureSQLiteSnapshot` artifact, rejects artifacts larger than 512 MiB, and pins the same trusted root/operation/file identities. On Linux it copies the pinned bytes while computing exact size/SHA-256 into a write/grow/shrink/seal-protected `memfd`, confirms all required seals with `F_GET_SEALS`, and re-hashes the frozen descriptor; only those reverified bytes are exposed to the pinned driver's `NewRestore` through `/proc/self/fd`, closing pathname, same-inode, and pre-seal substitution races. `NewRestore`, bounded positive-page steps, source identity checks, and exactly one `Finish` remain inside one fresh destination connection's `Raw` callback; its connection-owned in-memory database is then checked for exact `PRAGMA integrity_check = ok`, zero `foreign_key_check` rows, a read-bounded complete embedded migration set with exact checksums and no newer version, and six control-table counts. The original source hash/size/identity must still match before the destination is discarded. Stage-only errors preserve cancellation without returning paths, hashes, SQL, contents, or driver errors. Focused parent commands after correction: `go test -count=10 ./internal/database` passed; `go test -race -count=1 ./internal/database` passed; `go vet ./internal/database` passed; Linux/amd64 test-binary cross-compilation passed; `git diff --check` passed. Tests cover Capture→restore counts, source byte/identity stability, metadata size boundaries, wrong metadata, same-size mutation, corruption, foreign-key violations, missing/mismatched/newer/excessive migrations, pre-cancellation, bounded step/Finish behavior, producer namespace canaries, missing-source non-creation, and Linux pathname/same-inode ABA, complete-seal enforcement, and pre-seal tampering regressions. The read-only URI uses `immutable=1` only to suppress WAL/SHM sidecars for the sealed standalone artifact; trust comes from verified kernel seals plus before/after identity and digest checks. Non-Linux restore verification is development-only. No installer wiring, manifest publication, persistent clean-host restore, PostgreSQL/Redis/config restore, retention, encrypted off-host copy, Linux execution, COMPATIBILITY.md §6, or production acceptance is added. OPS-004 and NFR-010/011 remain Partial.

Final parent gates after the sealed-source correction: `go test -count=1 ./...` passed; `go test -race -count=1 ./...` passed; `go vet ./...` passed; `go build ./...` passed; Git Bash `deploy/tests/run.sh` passed **142/142**; `gofmt -l internal/database` was empty; and `git diff --check` passed. Live-service integration cases remained skipped without configured services. Linux runtime execution of the `memfd`, ownership, mode, symlink, and replacement regressions remains required; cross-compilation is not runtime evidence.

### OPS-004 / NFR-010 `redgres backup` command (SQLite capture/verify/retention) (2026-08-27)

Partial, not OPS-004 or NFR-010 Complete. `cmd/redgres/backup.go` adds a `backup` subcommand (wired in `cmd/redgres/main.go`) that runs the SQLite control-state backup lifecycle end to end: `internal/backupops.Capture` (calls `database.CaptureSQLiteSnapshot` then `database.VerifySQLiteSnapshotRestore`; a verification failure returns the error and leaves the snapshot for retention/operator cleanup) and `internal/backupops.ApplyRetention` (non-recursive `os.ReadDir`, exact `redgres-sqlite-`+48-hex producer-namespace match, `Lstat` real-directory/symlink rejection with a pre-removal identity re-check, `ModTime`-desc sort, never deletes the newest, `keep<1`/empty/relative/missing-root/canceled-context fail closed; returns only relative names). `runBackup` uses its own `flag.FlagSet` (`-sqlite-path` default `REDGRES_SQLITE_PATH`, required absolute real-dir `-staging-root`, `-keep` default 7), `signal.NotifyContext`, and prints a secret-safe summary (SHA256, SizeBytes, SchemaVersion, six control-table counts, removed names) without the snapshot path or staging root; it does not call `database.Migrate` (backup never mutates the source). Commands actually run: `go test -count=1 ./...` passed (18 packages); `go vet ./...` passed; `gofmt -l cmd/redgres internal/backupops` empty; `go build ./...` passed; `git diff --check` passed. Tests cover a migrated six-table control state (SHA256/size/SchemaVersion=2/counts, producer namespace/path shape, source usable after capture), relative-root and canceled-context rejection, snapshot-survives-verification-failure, retention keep=7 removing exactly the oldest, newest never removed, unrelated/canary/producer-named-file/symlink untouched, and the fail-closed table. Not implemented (deferred): manifest `current.json` publication, PostgreSQL `pg_dump`/`pg_dumpall`, Redis BGSAVE/AOF, off-host copy, HTTP backup API, installer (`deploy/`) wiring, whole-set restore, and production evidence. Linux-only `memfd`/mode/symlink runtime proof still required. Do not mark OPS-004, NFR-010, or COMPATIBILITY.md §6 Complete.
