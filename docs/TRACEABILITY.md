## Current slice

### Fresh PostgreSQL provisioning prerequisites (2026-08-31)

PG-003 / PG-005 / OPS-001 / NFR-006 Partial: the fresh installer now converges `redgres_admin` to bounded `LOGIN CREATEDB CREATEROLE NOSUPERUSER NOREPLICATION`, creates and protects `database_console_vault.public.project_credentials`, and generates one stable root-owned Fernet source before application startup. A root-only managed-key marker keeps that source selected across privileged upgrades; app-writable `redgres.env` can neither suppress it nor downgrade the installed service from production mode. Without a trusted marker the installed unit clears the vault variable and fails create/reveal closed. Upgrade may adopt exactly one descriptor-pinned, bounded, root-owned legacy source only through an explicit one-time root-owned adoption manifest; missing authority, unsafe metadata, disagreement, or collision fails before service mutation. Rollback to a pre-1.1.9 reader preserves the root source and creates only a service-private `0600` runtime copy. Fresh mode rejects a pre-existing vault env key before package, service, or cluster mutation. Password input to PostgreSQL-superuser SQL is restricted to the exact installer-generated base64 shape. Production accepts systemd's exact root-owned `0440` credential only under the active `/run/credentials/...` directory; ordinary group-readable files remain rejected. Evidence: Git Bash `deploy/tests/run.sh` passed 212/212; `bash -n`, `git diff --check`, `go vet ./...`, `go test ./...`, `go test -race ./...`, web build, and 473/473 frontend tests passed. The exact helper produced the required role/vault catalog state on Ubuntu PostgreSQL `18.6 (Ubuntu 18.6-1.pgdg26.04+2)` and digest-pinned `postgres:17.11@sha256:0b657ff48d7f76a1e907f381b1693eb4f2bf54c1d2df4feb6743d7dc601768dd` (`17.11 (Debian 17.11-1.pgdg13+2)`). On the authorized Ubuntu 26.04 host, exact Linux negatives rejected group-readable, symlinked, empty, oversized, wrong-owner, and writable-ancestor adoption inputs; explicit manifest adoption preserved exact bytes and consumed its authority. A real systemd oneshot proved the generated pre-1.1.9 unit copied identical credential bytes into a service-private `0600` runtime file, while the 1.1.9 path used `%d` directly. An exact systemd application unit also proved the root source unreadable for writes and the runtime credential readable but non-writable; a real `postgresadmin.Open` → Create → Reveal password-equality → Drop run passed with zero database or vault-row leftovers. Independent ruthless review closed SQL-injection, false-green test, writable-key, env-precedence, preflight-order, generated-installer drift, adoption-collision, app-writable-selection, confused-deputy adoption, legacy-upgrade, rollback-compatibility, and race-gate blockers; the corrected immutable commit is the release-verification target.
